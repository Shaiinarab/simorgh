Get running in 3 steps

No account, no card, no build step. Pick where your core lives, mint an API key, then configure the Android app.

1 Start a core

Requires Node 22+ and upm (the repo's package manager). All three paths run the same engine.

git clone https://github.com/Shaiinarab/simorgh.git
cd simorgh
upm install
export NO_PROXY=127.0.0.1,localhost
upm run simorgh -- serve --port 8788

The core boots with zero keys — providers you have no key for simply show as dormant. Set provider keys (e.g. GROQ_API_KEY, GEMINI_API_KEY, OLLAMA_BASE_URL) before starting to wake birds.

git clone https://github.com/Shaiinarab/simorgh.git
cd simorgh
upm install
npx wrangler login
npx wrangler kv namespace create CONTEXT_STORE
# paste the returned id into wrangler.toml (binding CONTEXT_STORE)

Then set your secrets and deploy (step 2 mints the key; the deploy script typechecks first and refuses a broken tree):

wrangler secret put SIMORGH_API_KEY       # paste the generated token
wrangler secret put SIMORGH_API_KEYS      # paste the JSON map from step 2
upm run deploy
Zero-key guarantee: on Cloudflare, Homā (Workers AI) answers with no provider key at all — the only host where that is true.
git clone https://github.com/Shaiinarab/simorgh.git
cd simorgh
upm install
export NO_PROXY=127.0.0.1,localhost
export SIMORGH_API_KEY="<token>"
export SIMORGH_API_KEYS='{"<token>":"<user>"}'
upm run simorgh -- serve --port 8788

Put it behind systemd or a supervisor; put TLS in front (Caddy, nginx). The Node runtime reads process.env and nothing else — see docs/DEPLOY.md.

Heads-up: the shipped Node entrypoints keep SQLite in memory — the ledger and counters reset on restart. For durable state, call startNodeRuntime({ sqlPath: "/var/lib/simorgh/core.db" }) from your own entry point.

2 Mint your API key

A token is just a string you invent; the map SIMORGH_API_KEYS binds it to a user id. The Android app sends the token as a Bearer credential, and the core resolves the user from the token — never from a client claim.

export SIMORGH_API_KEYS='{"…":"…"}'
export SIMORGH_API_KEY='…'   # service token for CLIs; optional
Missing auth fails closed: with no key configured, every authed route answers 503 AUTH_NOT_CONFIGURED — never an open door.

3 Point the Android app at your core

Build the app from source (no prebuilt APK is published): with the Android SDK installed and android/local.properties pointing sdk.dir at it,

cd android
./gradlew assembleDebug
# APK: android/app/build/outputs/apk/debug/app-debug.apk

Install it, open Config, and enter exactly these three values — they are pre-filled from step 2 where possible:

On the Agent screen, send a prompt. A core with no provider keys still answers honestly: answered_by: "none" with a clear error — never a fabricated reply.

Verify from a terminal first: 
curl -s http://127.0.0.1:8788/health
curl -s -X POST http://127.0.0.1:8788/api/v1/agent/execute \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"prompt":"who is simorgh"}'

What the Android app talks to

Three screens, one contract (docs/api/CONTRACT.md). The credential is the only identity; a userId is a claim the core validates.

MethodPathAuthUsed by
GET/healthnoneStatus screen
GET/api/v1/flock/statusnoneStatus screen — which birds are awake
POST/api/v1/agent/executeBearerAgent screen — the tool loop + flock failover

Errors the app handles explicitly, and what they mean:

StatusCodeMeaning
401UNAUTHORIZEDmissing or unknown token — check the API key field
403FORBIDDENthe userId claim disagrees with the token — leave it blank
429RATE_LIMITEDhonour Retry-After; the flock is rate-limited, not broken
503AUTH_NOT_CONFIGUREDthe core has no key configured — set SIMORGH_API_KEY(S) and restart
503IDENTITY_UNRESOLVEDa read route saw the service token — use a mapped token (SIMORGH_API_KEYS)

Without keys it still tells the truth

Simorgh boots with zero secrets. A provider with no key is dormant, not broken: it is skipped without a cooldown and the flock answers from whatever is awake. On Cloudflare, Homā (Workers AI) is keyless by design. On Node, add a free key or point OLLAMA_BASE_URL at a local daemon to wake birds. If nothing is awake, the answer says so — answered_by: "none", never a hallucination.

۱ یک هسته اجرا کنید

نیازمند Node 22+ و upm (مدیرِ پکیجِ مخزن). هر سه مسیر همان موتور را اجرا می‌کنند.

cd simorgh
upm install

upm run simorgh -- serve --port 8788

هسته با صفر کلید بالا می‌آید — پروایدرهایی که کلیدشان را ندارید dormant می‌شوند. برای بیدارکردنِ پرنده‌ها کلیدها را (مثل GROQ_API_KEY، GEMINI_API_KEY، OLLAMA_BASE_URL) قبل از اجرا ست کنید.

git clone https://github.com/Shaiinarab/simorgh.git

upm install
npx wrangler login
npx wrangler kv namespace create CONTEXT_STORE
# شناسۀ برگشتی را در wrangler.toml (binding CONTEXT_STORE) بگذارید

سپس secretها را ست کنید و deploy کنید (قدم ۲ کلید را می‌سازد؛ اسکریپتِ deploy اول typecheck می‌کند و درختِ خراب را رد می‌کند):

wrangler secret put SIMORGH_API_KEY       # توکنِ ساخته‌شده را بچسبانید

۲ کلید API خودتان را بسازید

توکن فقط یک رشته است که خودتان می‌سازید؛ نگاشتِ SIMORGH_API_KEYS آن را به یک شناسۀ کاربر متصل می‌کند. اپ اندروید توکن را به‌عنوان Bearer می‌فرستد و هسته کاربر را از توکن استخراج می‌کند — نه از ادعای کلاینت.

export SIMORGH_API_KEYS='{"…":"…"}'
export SIMORGH_API_KEY='…'   # توکنِ سرویس برای CLI؛ اختیاری
احراز هویتِ ست نشده fail-closed است: با کلیدِ ست‌نشده، هر مسیرِ authed پاسخِ 503 AUTH_NOT_CONFIGURED می‌دهد — نه یک درِ باز.

cd android
./gradlew assembleDebug

بدون کلید هم راست می‌گوید

سیمرغ با صفر راز بالا می‌آید. پروایدرِ بی‌کلید dormant است، نه خراب: بدون cooldown رد می‌شود و گلّه از هر چه بیدار است پاسخ می‌دهد. روی Cloudflare، Homā (Workers AI) ذاتاً بی‌کلید است. روی Node، یک کلیدِ رایگان اضافه کنید یا OLLAMA_BASE_URL را به یک daemon محلی اشاره دهید. اگر هیچ‌چیز بیدار نباشد، پاسخ می‌گوید — answered_by: "none"، نه خیال‌بافی.
